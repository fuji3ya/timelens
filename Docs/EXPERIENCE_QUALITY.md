# Hero Scene 体験品質仕様（EXPERIENCE_QUALITY v1 — 2026-07-05）

> Phase 2 の実装仕様。`PLAN_V2.md` Phase 2 / Track C とセットで読む。
> 「15秒のうわすごい」は**スライダーという機能**ではなく**魅せ方の振付**で決まる。この文書はその振付の仕様。
> 原則: 最初に配る TestFlight ビルドも reputation event（First-Contact Quality）。「とりあえず動く版」を配らない。

---

## 0. 最重要ルール: 構図一致アセット（Composition-Matched Asset）

**過去景イラストは自由に描かない。観覧地点から iPhone 標準カメラ（26mm 相当）で撮った「基準写真」を元に、同じ視点・同じ画角・同じ構図で過去景を生成する。**

- 理由: 自由生成の過去絵と実カメラ映像は画角・視点高・パースが一致せず、手動位置合わせ UI をどれだけ磨いても「ズレたステッカー」にしかならない。**構図を生成時に一致させれば、位置合わせ問題そのものが消える**（ユーザーは観覧地点に立つだけでよい）
- Track C-3 の現地収集に「**基準写真の撮影**（観覧地点・向き固定・標準レンズ・目線高さ）」を必須項目として追加
- Track C-2 の生成は基準写真を入力にした image-to-image（構図保持・時代変換）で行う
- 合わせ目ガイド（屋根線・道路縁のゴースト輪郭）は「立ち位置の微調整ヒント」に格下げ（主役ではない）
- 時間帯・天候ミスマッチを減らすため、過去絵は**ニュートラル曇天〜夕方寄りの中間光**で生成する（快晴・夜専用絵は作らない）

## 1. リビールの振付（最初の 15 秒）

「写真がただ重なって表示される」を禁止する。初回体験は次のシーケンス:

1. **到着** — カメラ起動。画面には現在の景色 + 最小限の UI（ガイド輪郭がごく薄く呼吸）
2. **整いの合図** — **デバイスが静止していること（CoreMotion で判定）を必須条件**に、輪郭一致 or 3秒経過でガイドがすっと消えて haptic 一拍。「準備が整った」感。**ユーザーがまだ構図を探して動かしている間は絶対に発火しない**（「勝手に動いた」ストレスの回避）
3. **自動リビール（2.5〜3.0 秒）** — ユーザー操作なしで一度だけ、現在→過去へゆっくり自動遷移する。音（現在の環境音→過去の環境音）と色（後述のグレーディング）を同期。**ここが「うわ、すごい」の本体**
4. **主導権の手渡し** — 過去 100% で一拍置いてスライダーが出現し、以降はユーザーが自由に行き来する

- 自動リビールは**スポットごと初回のみ**。2回目以降は即スライダー
- 触った瞬間に自動リビールは中断してユーザー操作を優先（すべての演出は interruptible）

## 2. タイムスライダーの物理

| 項目 | 仕様 |
|---|---|
| 操作 | 直接操作（ドラッグ位置 = 時間量）。タップジャンプは無し |
| 端の挙動 | 0% / 100% でラバーバンド（わずかに行き過ぎて戻る） |
| 離した時 | 最寄りの端（現在 or 過去）へスプリングで静定。中間放置はしない |
| ハプティクス | 端到達で soft impact 1回。スクラブ中は無し（過剰にしない） |
| 中断可能性 | アニメーション中のタッチは常に即時優先 |
| Reduced Motion | 自動リビール→クロスフェードのみ（パララックス・スプリング演出を無効化） |

## 3. ブレンドの絵作り（「安っぽい写真合成」の回避）

素朴なアルファクロスフェードは中間値で「ズレた二重写し」に見える。3 層レシピで「記憶が滲む」表現にする:

1. **カメラ映像のグレーディング** — スライダー値 t に応じて現在の映像自体を過去絵のパレットへ寄せる（彩度↓・暖色シフト・コントラスト微調整）。現在と過去が中間で「同じ世界の色」になる
2. **過去絵の質感** — 微細グレイン + 周辺減光。**動的に計算せず、生成時（Track C-2）に絵へ事前ベイクする**（静的アセットにリアルタイム GPU を使わない）
3. **ジャイロ・パララックス** — 過去絵を端末の傾きに応じて ±4px 程度だけ追従（トラッキング不要・Reduced Motion では無効）。**CoreMotion 生値は使わず low-pass filter を通す**。基準写真と実映像の画角ズレが目立つ端末/条件では自動で無効化（浮遊感が出るくらいなら切る）

**負荷設計（実機の熱・フレームドロップ対策 — 2AI 指摘反映）**:
- リアルタイム GPU 処理は「カメラ映像のグレーディング1系統」だけに絞る。フィルタは単一チェーンに合成し、`CIContext` を再利用（毎フレーム生成禁止）。それでも足りなければ Metal 直
- 実機での熱・フレームレート実測を Phase 2 のチューニング項目に明記（TestFlight ビルドで計測）

**音の設計（現実の音はすでに鳴っている）**:
- 現在側の環境音をアプリから再生しない — **ユーザーの耳にはリアルの現在音が既に聞こえている**。アプリが扱うのは過去側の環境音のみで、t に応じてフェードイン/アウトする（片側フェード）。これにより「二重の現在音」問題とクロスフェードの同期難を構造的に回避
- **無音でも体験が成立する**こと（字幕・視覚のみで完結）
- 手ブレでカメラ映像は揺れるが過去絵は固定 — 中間ブレンドを長時間見せない設計（スプリングで端に静定）で「ズレの観察時間」を最小化する

**抑制の原則**: 演出は足すより引く。1画面1主役（主役は常に「景色の変化」）。グレイン・パララックス・ハプティクスは「気づくか気づかないか」の強度に留め、1つでも主張し始めたら弱める

## 4. Mode D（シネマティック・フォールバック）の仕様

エラー画面ではなく「別のレンズ」。Mode A と同じ文法で作る:

- 基準写真（現在・静止画）と過去絵の**同一スライダー体験**。カメラが無いだけで振付・音・グレーディングは §1〜3 と同一
- 導入コピーは「使えません」でなく「ここから、当時の◯◯を覗けます」
- Ken Burns（ゆっくりズーム/パン）を過去絵 100% 静止時に適用し、静止画でも生きている感を出す
- カメラ/位置拒否・ARKit 非対応・屋内起動、すべてこのモードに自然合流

## 5. レビュー/デモ・モード（App Store 審査対策 — 必須）

**Apple の審査員は現地に行けない。** 位置ゲートされた体験はそのままでは審査不能で、2.1（機能が確認できない）や 4.2 の温床になる:

- **出荷ビルドに「デモ体験」導線を用意する**（隠しではなく、設定 or スポット詳細から「ここに行けない場合: プレビュー体験」）。実体 = Mode D（基準写真ベース）なので追加実装コストはほぼゼロ
- UI 上で **「プレビュー（サンプル体験）」と明示ラベル**する — 審査員が「本物の体験か制限された機能か」を混乱しないため（Gemma4 指摘）
- デモ体験はペイウォールのプレビューを兼ねる（有料スポット1本の冒頭 10 秒だけ見せる等は Phase 4 で判断）
- **IAP の審査可能性（Phase 4 で必須）**: 購入 → 有料スポットのデモ体験がアンロックされる流れを、審査員が現地に行かずに一通り確認できること
- App Review ノートに: デモ導線の場所・観覧地点座標・IAP テスト手順を明記（Phase 6 チェックリストへ）
- `#if DEBUG` の位置バイパスとは別物（あちらは開発専用でリリースに存在しない）

## 6. 品質ゲート（Phase 2 の Definition of Done に追加）

1. **HTML モック先行** — Experience 画面（リビール振付 + スライダー + グレーディング）を HTML/CSS/JS で先に実装し、Windows 上でスクショ/録画して磨く。基準写真+生成過去絵の実ペアで検証する（design-reference-first）。**マウス移動をジャイロに見立てた擬似パララックスまで含め、タイミング数値（リビール秒数・スプリング定数・フェードカーブ）をここで決め打ってから移植する**（Gemma4 指摘: 実機でしか見えないのは熱/ハプティクス/実ジャイロだけに絞る）
2. **モーション検証** — 録画→フレームダンプで pop/hitch/グリッチをフレーム単位検査してから SwiftUI へ移植
3. **移植 parity** — CI の UI テストスクショ artifact で HTML 版と並べて差分確認
4. **床/天井ゲート** — AI っぽさチェック + 「売れてる AR/カメラ系アプリと同じリーグに見えるか」
5. **定量バー** — 到着から最初の wow まで ≤15 秒 / 体験ログでスライダー往復中央値 ≥3（触りたくなる証拠）/ クラッシュ・白画面 0

## 7. 実装配置（Phase 0 アーキテクチャとの接続）

- 振付・ブレンドは `Features/Experience/` 配下、カメラ/CIFilter は `Infrastructure/AR/` に閉じ込め、View へ漏らさない
- `ExperienceDefinition` に将来 `referencePhotoName`（基準写真）を追加（Phase 2 のスキーマ変更。overlayAssetName とペア）
- 体験ログは `AnalyticsSink` プロトコル経由（V1 はローカルのみ、§8 プライバシー原則どおり）
